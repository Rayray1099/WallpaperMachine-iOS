## Active native-scene frame investigation

The user reports **“The scene has not produced a native Metal frame. Check its assets and renderer diagnostics.”** Import success does not resolve this failure. Device testing is paused while the user is away; no further iPad contact is authorized until they return.

Source inspection and an actual local C++ filesystem/package reproduction identified a startup prerequisite: the iOS host computes `Application Support/WallpaperMachine/SharedAssets` but creates only its shader cache, while `MainHandler::loadScene` requires the shared directory to exist before it mounts the wallpaper's own files. With no directory, loading returns early without publishing a backend failure, so the UI eventually reaches its generic 15-second deadline. The reproduced filesystem contract fails for the missing folder and succeeds after creating an empty folder; this does **not** establish GPU rendering or prove the exact filesystem state on the user's iPad.

## Platform and authorization boundaries

This is an in-app native renderer plus file export. Public iOS APIs do not allow arbitrary continuous third-party Home/Lock Screen rendering or unrestricted other-app audio capture. Author previews, actual engine playback, file conversion, AirCard import and system application are distinct. Only user-authorized Workshop/assets may be downloaded or imported; Wallpaper Engine's licensed shared resources are not redistributed. Personal device screenshots/traces, credentials, the supplied dylib and local injected IPAs stay out of Git.
